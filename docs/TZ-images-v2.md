# «Зверята 2.0» — стандарт изображений

Нормативный документ для коллекции **142 карточек** в `catalog/catalog-v2.json`. Из них **141 новое изображение** создаётся по одному; №001 пропускается на этапе генерации. Основное ТЗ приложения — [TZ-v2.md](TZ-v2.md).

## 1. Что генерируем

- Для каждой карточки создаётся **одна самостоятельная вертикальная фотореалистичная фотография 9:16** с **одним животным**.
- Вид, конкретная разновидность или порода (если указана) и возраст определяются только полями `reference` и `stage` каталога.
- **Индивидуальных сценариев фотографий нет.** Генератор самостоятельно выбирает естественную позу, ракурс, окраску в допустимых для вида пределах и реалистичное окружение. Не закреплять за ID цвет шерсти, положение тела, предметы, локацию или композиционные схемы.
- Критерий результата: ребёнку сразу понятен вид животного; полный читаемый силуэт, правильная анатомия, все существенные части тела в кадре.
- Естественный фотографический вид: реалистичная шерсть, кожа, перья, чешуя и пропорции, спокойный свет, узнаваемая, но визуально ненавязчивая среда.
- Изображение занимает весь кадр без надписей, интерфейса, рамок и заставок. Название и чёрная шапка добавляются отдельно приложением.

Эти требования относятся ко всем животным **одинаково**. Если естественная поза скрывает важные отличительные признаки, нужно выбрать другой удачный кадр; отдельное режиссёрское указание заранее не задаётся.

## 2. Формирование запроса

Для каждого ID планировщик читает `reference` и `stage` из каталога и подставляет их в единый [чистый шаблон](IMAGEGEN-CLEAN-PROMPT-v2.md). Скрипт `scripts/make_generation_briefs_v2.py` может сформировать аналогичные отдельные задания автоматически.

- Генерационный вызов содержит только **одно** конкретное животное и общие фотографические требования.
- Не передавать генератору весь каталог, имена других животных, состав партии, историю обработки, журналы и документы целиком.
- Не вводить индивидуальные инструкции по позе, цвету или фону на основе названия карточки. Биологическая достоверность и видовые признаки — критерий приёмки, не сценарий кадра.
- Качество проверяется **после** каждого результата. Если фото не соответствует виду, возрасту, анатомии или формату одного кадра, отклонить и при необходимости повторить чистый предметный запрос.
- При систематической структурной ошибке не зацикливаться; пометить ID как `blocked`, использовать независимый контекст при технической возможности и двигаться дальше.

## 3. Этап 1 — создание оригиналов

Текущий исполнительский документ — [MASTER-PROMPT-GENERATION-ONLY-v2.md](MASTER-PROMPT-GENERATION-ONLY-v2.md).

Генерация идёт по точному порядку `catalog/catalog-v2.json`: первая — №002 `cat`; далее до №142, независимо от категорий. `catalog/batches-v2.json` задаёт 15 контрольных групп (14×10, последняя 2), **без подтверждений между партиями**.

Сохранять каждый удачный оригинал в `assets-v2/originals/` без модификации с ID в имени и SHA-256. После каждой карточки обновлять компактный `catalog/image-production-state-v2.json`: `completed[id]` — подтверждённые существующие исходники, `blocked[id]` — отмеченные проблемы; остальные ID считаются не начатыми. Не отмечать как `approved` изображение, прошедшее только первичную проверку.

На этом этапе не выполнять массовую конвертацию WebP, сборку обзорных листов, ZIP и Android APK. Если среда выполнения прерывается, сохранять фактический прогресс.

## 4. Этап 2 — приёмка и оптимизация

После полного прохода каталога используется [MASTER-PROMPT-IMAGE-PRODUCTION-v2.md](MASTER-PROMPT-IMAGE-PRODUCTION-v2.md).

Для каждого изображения проверить правильность вида/возраста, силуэт и анатомию, естественный фотографический характер, читаемость на экране телефона. Принятие невозможно только по наличию файла либо хеша. Неуспешные кадры исправляются по ID, остальные сохраняются.

Подготовка технических кандидатов: `scripts/prepare_photo_v2.py --id <id> --input <path>`. Целевые файлы — `RGB WebP 1440×2560`, **не более 2 500 000 байт на файл**, все фото суммарно **не более 200 MiB**. Сохранять пропорции животного, не обрезать важные части. При исходнике ниже целевого размера записать `upscaled`, не приписывая ему дополнительную детализацию.

Принятые WebP хранятся в `assets-v2/approved/webp/`, неизменённые оригиналы — в `assets-v2/originals/`. Файл `assets-v2/approved/sha256.json` должен иметь по одной записи на каждый из 142 ID: `status: approved`, `sha256` WebP, `original_sha256`, `original`, фактические `review_notes`.

Обзорные листы 2×5 и ZIP создаются **программно из сохранённых файлов только на этапе 2**, а не запросом генерации изображений.

## 5. Готовность к APK

`scripts/package_content_v2.py --mode release` должен проверить все 142 утверждённые карточки: число, каталог, размер WebP, совпадение хешей и оригиналов, статус визуальной проверки. Ни пропущенные, ни непроверенные файлы в релиз не допускаются. Предварительный каталог и режим `preview` не означают готовности новой коллекции.

Правила подписи APK, интерфейса, свайпов, таймера, офлайн-работы и тестов определены [полным ТЗ приложения](TZ-v2.md). Они не входят в первый этап генерации.
